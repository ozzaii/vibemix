<objective>
Make the in-bar reaction-timing + cooldown surface explicit, test-pinned, and one-line tunable — so the LIVE-03 "reactions land in-bar, not after the moment passes" contract is data-driven and a tuning change (after Kaan's live drive) is a single constant edit + restart, never a re-plan.

Critical grounding (54-RESEARCH Q3): the cooldown VALUES are v4-tuned/byte-identical and live in vibemix/audio/constants.py (MIN_EVENT_GAP_PER_TYPE PHASE=10/MIX_MOVE=14/LAYER_ARRIVAL=10, EVENT_GLOBAL_MIN_GAP=10, HEARTBEAT_SEC=45). The replay harness already has a --print-cooldowns mode that reports measured-vs-locked per-type gaps. This plan does NOT redesign cooldowns — it (a) adds the missing IN_BAR_TOLERANCE_S constant so in-bar timing is a named, editable knob, (b) pins cooldown-respect behavior with a real-detector regression, and (c) wires the --print-cooldowns instrument over the genre-1 captured trace so the Kaan-action tuning pass has data.

Output: one constant + a cooldown-grounding test + a --print-cooldowns-over-real-trace assertion. No existing cooldown value changed.

EventDetector._cooldown_ok(ev_type, now): returns (now - last_per_type) > gap AND
  (now - last_event_at) > EVENT_GLOBAL_MIN_GAP. So a second same-type event needs BOTH
  the per-type gap AND the 10s global gap to elapse.

--print-cooldowns (scripts/eval/replay_harness.py): _emit_cooldown_report(measured_gaps)
  emits per-type median inter-event gaps vs MIN_EVENT_GAP_PER_TYPE to stderr, WARNING when
  |delta| > COOLDOWN_REPORT_TOLERANCE_S (1.0s). main([...,"--print-cooldowns"]) runs it.
  tests/eval/test_replay_harness_cooldowns.py exercises both the pure emitter + the CLI flag.

psutil — `psutil==7.2.2` is already a dep (pyproject.toml:63). For RSS of a target pid: `psutil.Process(pid).memory_info().rss`. For the in-process synthetic soak, sample `psutil.Process()` (self) RSS.

PlaybackQueue (src/vibemix/audio/buffers.py:337):
  - `pull(n_bytes)` zero-pads on empty/partial: when `self._buffer` is empty it calls `levels.decay_voice()` and returns `b"\x00"*n_bytes`; on partial-fill it pads. There is NO underrun counter today.
  - An UNDERRUN (dropout) for soak purposes = an empty pull (full zero-pad) that occurs while the session is expected to be producing voice, OR any partial-fill pad. For a SYNTHETIC soak the harness drives push/pull itself and counts pulls that returned all-zero or partial.
  - `Levels` is the ctor dependency; construct a real Levels (or a minimal stub satisfying update_voice/decay_voice) for the synthetic drive.

pytest markers available: `slow`, `integration`, `cli` (pyproject.toml:199-206). The soak test = `slow`; the CLI smoke (if added) = `cli`.

<underrun_decision>
<!-- RESEARCH §3 decision. -->
- Do NOT mutate the prod PlaybackQueue hot path. Count underruns in the SOAK HARNESS by driving a PlaybackQueue and inspecting pull() return bytes (all-zero of length n OR shorter-than-requested-then-padded = underrun/dropout). This keeps the audio hot path untouched while still exercising the real queue semantics.
- RSS: assert on GROWTH not absolute. Sample baseline RSS after warm-up (first ~1-2s), then final RSS; assert `final <= baseline + budget_bytes` (small absolute budget) AND/OR slope under threshold across samples. Mirror test_60min_soak.py's tolerance philosophy.
- Duration: read from a `--seconds` CLI arg / `VIBEMIX_SOAK_SECONDS` env, default to a SHORT value for the automated test (e.g. 60-120s synthetic; the test may shrink further with a scaled tick count like test_60min_soak.py does to keep wall-clock low). The real ≥30-min run is `python -m vibemix.runtime.soak --seconds 1800` against a live pid.
</underrun_decision>

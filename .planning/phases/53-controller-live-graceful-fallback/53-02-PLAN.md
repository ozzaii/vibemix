<objective>
Close the BRINGUP-03 live-wiring gap and prove disconnect/reconnect deterministically. At HEAD the hot-plug watcher (`port_watcher_task`), the production callback (`handle_port_change`), and the macOS `start_port_watcher` all exist and are unit-tested in isolation — but `__main__.py` NEVER starts the watcher. So today a mid-session unplug/replug is undetected: the static listener silently retries, `is_connected()` stays stuck True, and (pre-Plan-01) stale moves leaked. This plan (1) wires the watcher into the live session on a dedicated asyncio stop event with proper cleanup, (2) fixes the capture-once-then-rebuild divergence by using a SINGLE-STATE callback that mutates the ControllerState the live loops already hold (option B — lowest risk for Kaan's single-FLX4 target), (3) proves disconnect->reconnect mid-session through the production callback and through the watcher+callback composed, and (4) ships a runnable macos_audio live-drive recipe for Kaan's physical sign-off.

Purpose: this is the unlock that makes "graceful fallback when the controller is unplugged" REAL in a running session rather than dead code. Combined with Plan 01's ring-clear, an unplug now genuinely degrades cleanly: detected within ~2s, is_connected flips False, stale moves gone, session keeps running on audio alone; replug rebinds and decode resumes on the same state object the coach/event-detector read.

Output: a single-state callback in `_midi_common`, a small `start_port_watcher` adjustment, the `__main__` wiring + cleanup, two integration tests, a main-wiring guard test, and a macos_audio live recipe. Depends on Plan 01 (mark_disconnected must already clear the rings).
</objective>

<objective>
Close BRINGUP-02's grounding contract with regressions, building on what already shipped — do NOT re-implement anything. The audio capture path (BlackHole 48 kHz → resample_poly → AudioBuffer) and the 48 kHz sample-rate guard (`assert_device_sample_rate`, called at every stream open in `_audio_macos.py`) are already wired at HEAD; the BPM median-ring stabilizer (`_stabilize_bpm`) shipped in `fd25337`. This plan PINS three grounding guarantees with automated tests so a future regression can never silently re-open them: (1) the 48 kHz guard fires for the listening INPUT device, (2) the bus-facing `state.bpm` never exceeds `BPM_VALID_MAX` on a real harmonic-leak trace (the live BPM=200 bug), (3) the other audio-derived features stay finite + in-range. It also ships a runnable `macos_audio` live-tap recipe so Kaan's real-hardware sign-off (meters move, bpm in-band) is one command.

Purpose: this is the sensing-trust foundation. Phases 54/55 (hype/coach) consume these features; if BPM=200 or a NaN band leaks, every downstream reaction is hallucinated. The bar is "the AI never sees a value that did not happen."

Output: three new regression test files + a live-recipe addition to the existing macos_audio smoke. No production source is modified in this plan (the production paths already exist) — except if a regression EXPOSES a real leak, in which case the minimal source fix is in-scope and documented.
</objective>

<objective>
Build the core of Kaan's directive: a grounded DSP genre AUTO-detector. Today the active profile is env-pinned at startup and never self-corrects from the audio (the reason psytrance misclassified). Add a continuous detector that picks the active GenreProfile from REAL features already on hand each tick — stabilized BPM band + band-signature match + crest factor — scored nearest-match across the (now psytrance-inclusive) profile library. It is pure numpy on existing features: no CLAP/MERT/OpenL3, no new heavy deps, zero per-tick API cost.

Anti-slop is non-negotiable ([[project_anti_slop_grounded_gemini_thesis]]): a confidence gate with an `unknown` fallback (never a false-confident guess), hysteresis so genre doesn't flicker bar-to-bar, and an explicit env override that wins when the user pins a genre. The detector is additive — it writes new `detected_genre`/`genre_confidence` MusicState fields and (when env is not pinned) drives `set_active_profile`; it does NOT replace the existing coarse `active_genre`/`_classify_active_genre` renderer signal.

Purpose: this closes the GENRE-01 grounding gap — the system can finally self-correct the active profile from what is actually playing, which is what makes the downstream phase thresholds + band gates (and therefore the AI's reactions) correct for psytrance instead of running under techno's wrong shape.

Output: a new detector module, two additive MusicState fields, the tick wiring (single-writer-safe), the env-pinned flag plumbing, and a thorough anti-slop test suite.
</objective>

<design_notes>
<!-- Recommended grounded design (autonomous: resolve grey areas). -->
1. Module src/vibemix/state/genre/genre_autodetect.py exposes:
   - score_genre(bpm: float, bands: dict[str,float], crest: float, profiles: list[GenreProfile]) -> tuple[str, float]: returns (best_name_or_unknown, confidence). Pure function, fully unit-testable without audio.
   - A GenreHysteresis dataclass + apply (mirror HysteresisState/_apply_hysteresis): N-tick dwell (recommend 3 ticks at the 10Hz tick cadence; the detector runs every tick but the score is dominated by the 3s-updated bpm, so a 3-dwell is ~real-time-stable). Below-threshold raw -> "unknown" commits like `silent` does in the phase detector (immediate, anti-hallucination).
2. Scoring (pure numpy, grounded): per profile, compute a sub-score on each axis in [0,1]:
   - BPM axis: 1.0 if bpm within bpm_range; else a linear falloff by distance to the nearest edge over a tolerance window (e.g. 10 BPM), floored at 0. bpm<=0 -> axis 0 (no BPM lock).
   - Band axis: for each of sub/low/mid/high, 1.0 if the observed share is within the profile's [lo,hi]; else falloff by distance / band-width. Average the 4.
   - Crest axis: 1.0 within expected_crest_factor; else falloff. crest<=0 -> neutral (0.5) so a missing crest doesn't dominate.
   - Confidence = weighted mean (recommend BPM 0.4, bands 0.4, crest 0.2 — BPM + bands are the strongest psy-vs-techno discriminators). The best profile's confidence is returned with its name.
3. Confidence gate: GENRE_CONFIDENCE_MIN (recommend 0.55) — below it OR best-minus-second < GENRE_TIE_MARGIN (recommend 0.08) -> ("unknown", best_confidence). Put both constants in audio/constants.py (or a genre constant near the detector) with a load-bearing comment.
4. Env override: in __main__.py after applied_genre = apply_genre_env(), set a module-level flag (e.g. genre_autodetect.set_auto_enabled(applied_genre is None)) — auto-detect runs only when env did NOT pin a real genre. When applied_genre is a real name, the detector still SCORES (so detected_genre/genre_confidence are still surfaced for honesty) but does NOT call set_active_profile. Thread this as an explicit param/flag, NOT inferred from get_active_profile().
5. Single-writer: the score+hysteresis happen in _tick_once; detected_genre/genre_confidence are written inside the existing with state._lock: block; set_active_profile (when auto-enabled and the committed genre changed and is not unknown) is called there too. set_active_profile mutates a module singleton (not MusicState) so it is outside the strict single-writer-of-MusicState rule, but call it from the one tick path only.
</design_notes>

## Decisions Made

1. **PyAV `format='fltp'` (planar) over `format='flt'` (interleaved) for `load_audio_stereo`:** Planar gives `r.to_ndarray()` shape `(channels, samples)` which transposes cleanly via `.T` to `(samples, channels)`. The interleaved variant returns shape `(1, channels * samples)` and requires an extra reshape pass. Same final shape, but planar is the cleaner contract and matches PyAV's documented planar/non-planar split (`av.AudioFormat('fltp').is_planar == True`). The verbatim RESEARCH §Pattern 7 source used `flt` which would have produced shape `(1, 88200)` for our 1-second 44100 Hz mono → stereo upmix fixture — and the test asserts `samples.shape[1] == 2`. Fixed at the implementation level (cleanly) rather than reshaping the output downstream.

2. **Reject `bool` BEFORE `int` in `_apply_learn_headphone_device_index`:** Python's `bool` is a subclass of `int` (`isinstance(True, int)` is `True`) so a corrupted IPC payload of `true` / `false` would silently map to device `0` / `1` — the worst kind of latent footgun for an audio routing surface. The reader `read_learn_headphone_device_index` applies the same guard for defense-in-depth on disk-corruption paths.

3. **`getattr` fallback for the master-RMS field:** `MusicState` exposes the RMS scalar as `rms` (line 31 in `src/vibemix/state/music_state.py`) but the verbatim RESEARCH §Pattern 6 source and the test stubs use `audio_rms`. Used `getattr(state, 'audio_rms', getattr(state, 'rms', 0.0))` so the player works with the `MagicMock` test stubs (which set `audio_rms`) AND the real `MusicState` (which exposes `rms`) without forcing a state-field rename (which would ripple into 50+ readers across the codebase).

4. **Forward-typed `state: MusicState` kwarg via `TYPE_CHECKING`:** Avoids an import cycle (`state/music_state.py` is read by `audio/buffers` and the agent path, which would create a `learn → state → audio/buffers → ...` loop if the import were runtime). The annotation is the contract; the runtime accepts duck-typed objects with the right attributes (a `MagicMock` for the test path; a real `MusicState` for the production path).

5. **P93 `can_play()` SCAFFOLDING evaluates the seam attributes but ignores the result:** The body reads `getattr(self._state, 'session_active', False)` and `getattr(self._state, 'audible_deck', 'none')` — the locals document the seam P96 will activate. The body returns `True` unconditionally; Plan P96's diff is one line: `return not (state.session_active and state.audible_deck != 'none')`. Constructor signature stays byte-identical.

6. **Idempotent `.stop()` one-shot under the lock:** `self._on_stop = None` is read + cleared under `self._lock`, then the callable runs OUTSIDE the lock to avoid reentrancy (callers MAY `.play()` from inside their `on_stop`). Two consecutive `.stop()` calls without a prior `.play()` is a no-op — the stream slot is `None` and the cleanup path short-circuits.

7. **`PlaybackQueue` grep gate satisfied by paraphrase, not deletion of the architectural context:** The Pitfall 2 rule (mic-gating threat) is load-bearing context that future readers MUST see in the docstring. The verbatim literal `PlaybackQueue` MUST NOT appear in `audio_cue.py` source per the `inspect.getsource()` static check. Resolved by paraphrasing the docstring ("the mic-gated co-host playback queue at `audio/buffers.py:195`") which preserves the architectural context without leaking the literal class name.

8. **Rule-1 test-bug fix on `test_settings_state_carries_headphone_device_index_after_set`:** The planner's stub walked `schema.definitions.SettingsState.properties` (the wrapper-level keys: `type`, `ts`, `payload`) which never carries any settings field — every field lives inside `.properties.payload.properties` (`voice` / `mode` / `skill` etc. at schema lines 1380-1457). Same semantic contract preserved (either nested `learn` object OR flat `learn.headphone_device_index` satisfies the test); corrected path documented inline in the test docstring.

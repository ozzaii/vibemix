<interfaces>
The 9 controllers split into 3 size tiers by control count (informs sizing the authoring task):

**Small (FLX6, FLX10, DDJ-400, Hercules 300, Hercules 500, Numark)** — each profile has ~20-30 controls (2 decks + xfader + small FX section). SVG file ~60-90 lines.

**Medium (XDJ-RX3, DDJ-SX3)** — Pioneer all-in-one + Serato controller; ~40-60 controls (additional sample section, FX bank). SVG file ~100-140 lines.

**Large (DDJ-1000)** — rekordbox-pro flagship; ~70-90 controls (8 hotcue pads per deck, Beat-FX, Color-FX, sampler bank). SVG file ~150-200 lines.

The authoring process for each SVG is mechanical (per UI-SPEC §Asset Pipeline + research §Pattern 3):
1. Read the profile JSON's `controls` + `buttons` blocks — these enumerate the wire-key set the SVG must declare.
2. Look up the manufacturer's official hardware-diagram PDF (Pioneer DJ "Operating Instructions" / Hercules DJControl manual / Numark spec sheet) for the factual control layout. NO marketing photos. NO photo-lift.
3. Author the SVG to `viewBox="0 0 1280 720"`, with each interactive control wrapped in `<g data-control-id="<wire-key>" role="button" aria-label="${ARIA_LABELS[wire-key]}" tabindex="0">` + factual geometry (`<circle>`, `<rect>`, etc. with `stroke="currentColor"` ONLY) + dual-cue slots `<g class="cue-color"></g><g class="cue-shape"></g>`.
4. Add `data-cx` / `data-cy` on knob `<g>`s so the latency harness's pivot lookup works.
5. Run `cd tauri/ui && npx vitest run tests/learn/test_svg_profile_parity.spec.ts -- --reporter=basic` after each SVG and ensure the matching row goes GREEN.

The Hercules Inpulse 300-MK2 is NOT shipped here — research §Pitfall 3 + CONTEXT.md §Deferred Ideas. Both 300 and 300-MK2 render the `hercules_inpulse_300.svg` in P91; the §LEARN-MK2-DETECTION KAAN-ACTION resolves it in P97.

Wire-key convention recap (from Plan 05):
- Deck-bound CC: `<field>:<deck>` (e.g. `eq_hi:A`, `vol:B`).
- Master-section CC: bare `<field>` (e.g. `xfader`, `master_vol` if present).
- Per-deck boolean buttons: `<kind>:<deck>` (e.g. `play:A`, `cue:B`, `sync:A`, `jog_touched:A`, `loop_in:A`, `hotcue:A:1`..`hotcue:A:8` for pads).
- The profile's `field` in `controls` + `kind` in `buttons` determines the `<field>` portion of the wire key.

`controller-stage.ts` allowlist shape (extend the existing dictionary from Plan 05):
```
const SVG_LOADERS: Record<string, () => Promise<{ default: string }>> = {
  pioneer_ddj_flx4: () => import("../controllers/pioneer_ddj_flx4.svg"),

};
```
Unknown controller_id falls through to `_generic`.

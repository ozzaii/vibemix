<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| `config.json` (tauri-plugin-store) → app setup | The `primary_surface` value chooses which OS window is created at startup. The value is a closed tri-state enum; a malformed/unknown value decodes to the safe default (`Pill`), never an arbitrary surface. No remote input — config is local user state. |
| setup() surface branch | Reads one local config key and creates at most one overlay window. No new network surface, no new permission. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-62-04 | Tampering | `config.json` `primary_surface` value (hand-edited / corrupted) | mitigate | Closed serde enum (`Pill`/`Mascot`/`None`); `load_primary_surface` returns `PrimarySurface::default()` (Pill) on absent key, and `main.rs` calls `.unwrap_or_default()` so a decode error also falls back to Pill — a tampered value can never crash setup or select an out-of-band surface. |
| T-62-05 | Denial of service | overlay-build failure (pill OR mascot) bricking app startup | mitigate | Clone the mascot's non-fatal discipline (main.rs lines 148-161): the surface branch LOGS but does NOT bail setup, so the main session UI still comes up even if the chosen overlay fails to build. |
| T-62-06 | Repudiation / regression | mascot silently deleted/regressed by the demotion | mitigate | `mascot-audit` CI fence (path-scoped to `tauri/ui/src/mascot/**`) + Task 3 guard prove the mascot path is preserved (`create_mascot_window` still reachable via `primary_surface=mascot`); mascot.html byte-stable; no pill surface references it. |
| T-62-SC | Tampering | npm/pip/cargo installs | accept | This plan adds NO package (Rust config + setup wiring only; reuses shipped `tauri-plugin-store` + serde). slopcheck N/A — no new dependency in scope. |
</threat_model>

# Phase 56 — UI Design Contract

> Visual and interaction contract for the **mascot many-modes reactive surface** (LIVE-05 / LIVE-05a) and the 60fps render-budget floor it runs on (PERF-03). Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **Headline deliverable:** a *mode state machine* in `mascot.html` that drives the EXISTING 2D sprite rig off the rich bus signals it currently ignores. Anti-slop is the hard gate — every mode flip MUST correspond to a real musical/session event.

## 0. Rig Reality (read this before planning — autonomous-mode finding)

There are **two** mascot HTML surfaces in the tree. The planner MUST NOT confuse them.

| File | Lines | Rig | Wired to | This phase? |

**Decision (autonomous `fully`):** The LIVE-05/05a headline targets the **root `mascot.html` sprite rig**.
- *Rationale:* it is the file 56-CONTEXT names, the one `ws_bus.ws_broadcast` directly feeds the flat frame to, and the one the prompt scoped ("make the EXISTING rig react across modes"). The Three.js rig's existing state-machine + the `MASCOT_REACTIONS` whitelist (`tauri/ui/src/mascot/types.ts`) are the **event-taxonomy reference** the sprite state machine mirrors, so the two surfaces stay conceptually aligned for a future merge.

**Two known gaps the planner must resolve (flagged, not blocking the spec):**
1. **Sprite PNGs are missing from repo root** (`sprite-1/2/3.png` not present). The rig references 3 sheets; only 3 loudness tiers exist today. This phase needs ≥6 mode-distinct sprite states. **Planner decision required:** either (a) author/derive ≥6 sheets (richer art is Phase 57 Sexify — so use placeholder/recolored derivations here), or (b) drive mode distinction primarily via the **CSS/canvas treatment layer** (aura color, glow, bob amplitude, scale-pump, frame-rate, posture tint) over the existing 3 sheets until Phase 57 supplies per-mode art. **This spec is authored for path (b)** — mode identity is carried by the *treatment contract* below, which works on top of whatever sheets exist, so the state machine ships and is testable before art lands.
2. **Palette drift:** root `mascot.html` still uses the **stale cyberpunk** vars (`--cyan #00f0ff`, `--magenta #ff00d4`, `--purple #8b00ff`). The CDJ Whisper direction is **amber-only accent on warm-black**. This phase MUST reconcile the mascot palette to CDJ Whisper (see §Color). This is in-scope cleanup — the cyan/magenta auras are the single most "AI-slop" element on the current surface.

The mascot is a single floating overlay, not a layout-dense panel — spacing applies to its chrome captions (`#status`, `#hint`, `#overlay` insets) and to motion-amplitude tokens, all on the 4px grid.

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Caption padding (`#status`, `#hint`), LED-dot gap |
| sm | 8px | Caption inset from window edge (`2vh` → snap to 8px min) |
| md | 16px | n/a in overlay; reserved for parity with session panel |
| lg | 24px | n/a |
| xl | 32px | n/a |
| 2xl | 48px | n/a |
| 3xl | 64px | n/a |

Exceptions:
- **Overlay sizing is viewport-relative, not px-grid** — `#overlay` is `26vmin` square (intentional: the orb must scale with window size). This is the one allowed deviation; the sprite canvas is `512×512` internal resolution rendered into the vmin box.
- **Motion amplitudes are not on the spacing grid** — they are motion-budget tokens (see §Motion). Hover-bob is ±6px, mode-pump deltas are documented in the per-mode table.

## Color

CDJ Whisper: warm-black void dominant, **single amber accent** at 4 intensities. The cyberpunk cyan/magenta/purple is **retired** from the mascot.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (≈80%) | `#000` transparent void → the overlay window is transparent; the perceived dominant is the sprite silhouette (`#020203`) + warm-black aura falloff | Window bg (stays `transparent` — Tauri overlay invariant), sprite body, aura outer falloff to transparent |
| Secondary (≈10%) | `--silk #d6cfc7` at 40–65% alpha | The two captions, mode label, status text |
| Accent (≈10%) | `--amber #ff8a3d` (+ `--amber-deep #ff5a1a`, `--amber-pale #ffb88a`, `--amber-22 rgba(255,138,61,0.22)`) | **Reserved-for list below** |
| Destructive | not applicable | The mascot has no destructive action |

**Accent reserved for (explicit — never "everywhere"):**
1. The **aura** (replaces cyan/magenta gradient) — amber radial, intensity modulated by mode.
2. **Mascot eyes** — the two tight amber points (brightest pixels, smallest area — per the mock's 20/80 §04).
3. The **voice glow** drop-shadow while the AI talks (`speaking` mode).
4. The **`#status` live-dot** (currently `#5f5` green — keep green for the *connection-OK* LED per the LED palette; amber is for *mascot energy*, green for *bus-health*. These are deliberately different semantic colors: green = "bus connected", amber = "musical energy". This is the one allowed second color and it is confined to the 6px health dot.).
5. The `.firing` manual-trigger flash (brightness/saturate pulse — amber-biased).

20/80 test the checker will apply: at rest (idle mode) the surface is ~95% warm-black void with two amber eye-points; only `drop` mode is allowed to push amber toward the 20% ceiling. If amber bleeds across every mode at full intensity, the rule is broken.

## Mode State Machine (the headline contract)

The mascot reads the **flat mascot frame** broadcast by `runtime.ws_bus.ws_broadcast` @30Hz (`ws_bus.py:266-288`). It currently consumes only `d.music` + `d.voice`. The new state machine consumes:

| Bus field | Type / values | Drives |
|-----------|---------------|--------|
| `music` | float 0..1 (smoothed) | Energy tier, aura intensity, scale-pump |
| `voice` | float 0..1 | `speaking` mode entry, voice glow |
| `phase` | `"silent"` / `"groove"` / `"build"` / `"drop"` / `"breakdown"` | **Primary mode selector** |
| `mood` | `"hype-man"` / `"teacher"` / `"coach"` | **Variant tint** (which posture/expression family) |
| `emotion` | `"neutral"` / `"focused"` / `"hyped"` / `"concerned"` / `null` | Secondary expression nudge (eye intensity, brow) |
| `bpm` + `bpm_confidence` | float, 0..1 | Beat-locked bob ONLY when `bpm_confidence ≥ 0.6` (anti-hallucination — else free hover) |
| `beat_phase` (`= downbeat_phase`) | 0..1 fraction-through-bar | Beat-synced bob phase when locked |
| `detected_genre` + `genre_confidence` | str + 0..1 | OPTIONAL aura hue micro-shift within amber band (NOT a new color) when `genre_confidence ≥ 0.6`; ignored otherwise |
| `reaction_intent` (`last_reaction_intent`) | one of `MASCOT_REACTIONS` whitelist (`wave`/`point_left`/`point_right`/`fist_pump`/`nod`/…) or `null` | One-shot gesture overlay on top of the steady mode (does NOT change mode) |

### Source-of-truth thresholds (mirror the Python side — do NOT invent new ones)

From `vibemix.audio.constants`: `SILENT_RMS = 0.012`, `LOW_RMS = 0.040`, `PEAK_RMS = 0.110`. The mascot reuses these so its mode boundaries agree with `state.phase`. `emotion_router`: `RMS_HIGH = 0.18`, `RMS_LOW = 0.08`.

### The 6 modes (≥6 distinct, each gated to a REAL event)

Mode selection is **`phase`-led, music-confirmed** (defence-in-depth: trust `phase`, but a contradictory `music` level blocks the flip → anti-slop). Priority order top-to-bottom; first match wins.

| # | Mode | Entry condition (REAL event) | Anti-slop guard |
|---|------|------------------------------|-----------------|
| 1 | **`speaking`** | `voice > 0.05` (AI is talking) | Overrides every music mode — the mascot is *emoting at you*, beats music reactivity. Exits when `voice < 0.03` for ≥ dwell. |
| 2 | **`drop`** | `phase == "drop"` **AND** `music ≥ PEAK_RMS (0.110)` | BOTH required — `phase=drop` with quiet music is a misclassification, do NOT trigger the peak animation. |
| 3 | **`building`** | `phase == "build"` | Allowed even at mid energy (build is a rising verse). Eyes narrow, anticipation lean. |
| 4 | **`breakdown`** | `phase == "breakdown"` **AND** `music < LOW_RMS (0.040)` | Energy must actually be low; a loud "breakdown" classification is contradictory → hold previous mode. |
| 5 | **`idle`** (dead-air) | `phase == "silent"` **OR** `music < SILENT_RMS (0.012)` | The "nothing is playing" floor. `emotion == "concerned"` (≥30s dead air) deepens it (worried brow). |
| 6 | **`vibing`** (groove) | `phase == "groove"` **OR** (`music ≥ LOW_RMS` and nothing above matched) | The default "music is playing, steady" home state. |

> **6 distinct modes, each gated to a real bus event.** No timer-driven, random, or decorative mode flips are permitted — the checker will reject any mode entry not traceable to a bus-field condition in this table.

### Mood as variant tint (single character, many moods — NOT new characters)

`mood` does **not** add a 7th mode — it re-tints the *same* mode. One character, mood-varied expression family (per `project_mascot_as_vtuber_personality_surface`):

| `mood` | Expression family | How it reads across modes |
|--------|-------------------|---------------------------|
| `hype-man` | **Grin / open** — wider eye flare, bigger scale-pump on `drop`, looser bob | The party-mode default; `drop` pumps hardest here |
| `teacher` | **Attentive / level** — steadier eyes, smaller pump, even bob | Mid-restraint |
| `coach` | **Focused / narrowed** — tighter eyes, minimal pump, deliberate bob, brow set | The feedback-mode read; even `drop` stays composed (a coach nods, doesn't lose it) |

`emotion` (`hyped`/`focused`/`concerned`/`neutral`) is a finer nudge layered on the mood tint — primarily eye-glow intensity and brow. When `emotion == null` → no nudge (backward-compatible no-op, same as the Three.js rig contract).

### Hysteresis (anti-flicker — mirror `HysteresisState` philosophy)

Modes must NOT flip bar-to-bar. The state machine holds a `pending` candidate and only commits after a **minimum dwell**, mirroring the Python `HysteresisState` (pending_label / pending_ticks pattern in `state/phase.py`).

| Parameter | Value | Rationale |
|-----------|-------|-----------|
| **Min dwell per mode (commit delay)** | **400 ms** | A candidate mode must persist 400ms of frames (~12 frames @30Hz) before it commits. Below one bar at most tempos — fast enough to feel live, slow enough to never flicker bar-to-bar. |
| **`speaking` enter** | **immediate (0 ms dwell)** | When the AI talks the mascot must react instantly — latency here is felt. Entry is unguarded; only EXIT is dwelled. |
| **`speaking` exit hold** | **600 ms** | After `voice` drops, hold `speaking` 600ms before returning to the music mode — prevents flutter on inter-syllable gaps (mirrors the mic-gate hold-window philosophy in `MicBuffer`). |
| **`drop` enter** | **120 ms** | Faster than the global 400ms — a drop landing must hit hard and on-time. Still long enough to reject a single spurious peak frame. |
| **`drop` exit** | **800 ms** | Stay "dropped" briefly after energy dips so the mascot doesn't deflate mid-drop on a transient dip. |
| **Contradiction rule** | a frame whose `phase` and `music` disagree (table guard column) does NOT advance the pending candidate — it is treated as "no signal", and the current mode persists. | This is the core anti-slop mechanism: ambiguous input → no decorative change. |

> The existing `ws.onmessage` EMA smoothing (`smoothMusic = ·*0.55 + ·*0.45`, `smoothVoice = ·*0.4 + ·*0.6`) **stays** — it's the first-stage debounce. Hysteresis is the second stage on top of mode selection.

## Per-Mode Visual Contract

Each mode is distinguished by a **treatment vector** over the existing rig (sprite-tier/sheet IF available + aura + glow + bob + scale + frame-rate + eye state). This works whether the planner ships 3 sheets or 6 — mode identity is carried by the treatment, not solely the art. All values are amber-band; "intensity" = aura alpha + glow radius.

| Mode | Sprite tier* | Aura (amber) intensity | Eye state | Bob / motion | Scale-pump | Sprite FPS | Caption (`#mode-state`) |
|------|-------------|------------------------|-----------|--------------|------------|------------|--------------------------|
| **idle** | 0 (calm) | very low (≈0.10α, blur 24px) | dim, slow 7s flicker; `concerned`→ slightly dimmer + worried offset | slow free hover ±4px @ 0.8s sin (NOT beat-locked) | none | 12 fps | `IDLE · DEAD AIR` (or `… · LISTENING` if bus connected & emotion=concerned) |
| **vibing** | 1 (mid) | low-mid (≈0.30α, blur 28px) | steady amber, normal flicker | beat-locked bob ±5px on `beat_phase` IF `bpm_confidence ≥ 0.6`, else ±5px free @ 0.7s | tiny ±2% on beat | 16–22 fps (scales with `music`) | `VIBING · {genre or BEAT}` |
| **building** | 1 (mid) | rising (0.30→0.50α as `music` climbs, blur 30px) | **narrowing**, anticipation; brighter rim | bob amplitude grows with `music`; slight upward lean | rising ±3% | 22 fps | `BUILDING · TENSION` |
| **drop** | 2 (peak) | **high (≈0.55α, blur 30px), the one mode allowed near the 20% ceiling** | **wide flare**, brightest eyes; `hype-man` flares widest, `coach` stays composed | hard beat-pump bob ±7px on `beat_phase` | **big ±5% (hype-man) / ±3% (teacher) / ±2% (coach)** | up to 30 fps | `DROP · PEAK` |
| **breakdown** | 0–1 (calm) | falling (0.50→0.15α, blur 25px) | softening, half-lid; relief read | bob decays, longer period (1.0s) | none / decaying | 14 fps | `BREAKDOWN · CHILL` |
| **speaking** | current music tier (does not change art) | voice-aura ON: separate amber-pale radial, `opacity = min(voice*4, 0.85)`, `mix-blend-mode: screen`; glow drop-shadow `8px + voice*40px` | **most expressive** — eyes track talk energy, no flicker (the mascot is "looking at you") | gentle emphatic nod on syllable peaks (NOT random) | ±3% on voice envelope | holds music FPS underneath | `{mood} · TALKING` (e.g. `HYPE-MAN · TALKING`) |

\* *Sprite tier maps to whatever sheets exist. With only 3 sheets today (path b), tier 0/1/2 = calm/mid/peak; mode distinction beyond the 3 tiers is carried by aura+eye+bob+fps+caption. When Phase 57 supplies ≥6 per-mode sheets, the planner remaps tier→mode 1:1.*

**One-shot gestures (`reaction_intent`):** when the bus sets `reaction_intent` to a whitelist value (`wave`/`point_left`/`point_right`/`fist_pump`/`nod`/…), play a brief overlay gesture (a transform nudge or a one-cycle sprite if art exists) ON TOP of the current mode, then return. It does **not** change mode and is rate-limited to one per ~1.5s. Unknown/`null` intent = no-op (anti-hallucination — never invent a gesture).

## Motion / 60fps Budget (PERF-03)

The render loop must hold **60fps on an integrated-GPU MacBook** while the new mode machine runs. The mascot is a **pure personality surface — it must add ZERO latency to the audio/reaction path** (`project_mascot_as_vtuber_personality_surface`); it only *reads* the bus.

| Constraint | Budget / rule |
|-----------|---------------|
| **Frame budget** | 16.7 ms/frame. Mode-selection + hysteresis logic must cost **< 0.5 ms/frame** (it's a handful of float compares + a counter — trivially within budget). The sprite blit is the dominant cost and is unchanged. |
| **No per-frame allocation** | Mode/hysteresis state lives in **pre-allocated module-scope vars** (like the existing `frameIdx`, `currentTier`). No object/array creation inside `tick()`. The current loop already obeys this — preserve it. |
| **No per-frame layout thrash** | Drive ALL motion through `transform`, `opacity`, `filter` on CSS custom properties (`--music-scale`, `--voice-*`, `--bot-y`, plus new `--aura-alpha`, `--eye-glow`, `--bob-y`). **Never** animate `width`/`height`/`top`/`left`/box geometry per frame. The existing rig already does this — every new mode treatment must too. |
| **Sprite redraw gating** | Keep the existing `dirty` flag: only `ctx.drawImage` when the frame index OR tier changed. Mode changes that don't change the sprite frame must NOT force a redraw — only update CSS vars. |
| **Single rAF loop** | Exactly one `requestAnimationFrame(tick)` chain (as today). No second loop, no `setInterval` for mode logic — mode evaluation happens inside the existing `tick`. |
| **Transition timing** | Mode→mode visual transitions are CSS-eased on the custom props (`transition: 180–250ms ease-out` on the aura/glow/scale vars — matches the mock's 180ms button ease). Transitions are GPU-composited (transform/opacity/filter only). No JS-driven tween loops. |
| **`will-change`** | Keep the existing `will-change: transform, opacity` / `transform, filter` hints; do not add `will-change` to more than the ~4 animated layers (over-hinting costs GPU memory). |
| **Idle throttle (battery)** | In `idle` mode the sprite FPS drops to 12 and the bob is slow — fewer redraws when nothing's happening. Acceptable to keep rAF running (transparent overlay), but the dirty-gate means most idle frames do no canvas work. |

**Testable assertions (extend existing tests — do NOT invent new harnesses):**
- `tests/integration/test_mascot_dispatch_latency.py` — already pins p95 sidecar→client < 50ms (half of the 100ms MASCOT-08 budget). The mode machine adds webview-side work; the existing budget (10ms webview + 40ms slack) must hold — mode-select is < 1ms, so it does. Extend with a synthetic-frame mode-transition test.
- **Mode state machine test (new, per 56-CONTEXT §specifics):** feed synthetic ws frames `silent → build → drop → breakdown → voice>0` → assert the mascot enters the right mode for each, hysteresis prevents single-frame flicker, and an **ambiguous/contradictory frame (`phase=drop` + `music<PEAK_RMS`) does NOT trigger a mode change** (the anti-slop assertion).
- `tests/runtime/test_ttft.py` / `test_phase_41_latency_stack_integration.py` — unchanged; mascot adds zero to the reaction path (it only consumes the bus).

## Copywriting Contract

The mascot has minimal copy — captions and state labels. CDJ Whisper voice: terse, uppercase, hardware-label register. No AI-slop adjectives.

| Element | Copy |
|---------|------|

> Anti-slop check: no "Oops!", no "Something went wrong", no emoji, no "Powered by AI". Mode captions are hardware-readout style (`DROP · PEAK`, `BUILDING · TENSION`), not chatty.

<objective>
The metadata-richness refinement slice. Today `rekordbox.py` parses only the
spine (title/artist/bpm/key/duration/cues) and leaves real curated metadata on
the table. This plan reads the high-value fields the `collection.xml` export
already exposes — genre, label, rating, play_count, comments, the full TEMPO
beatgrid — normalizes the classical key to Camelot at parse time via the
deterministic `harmonics.to_camelot` table (the LLM never computes keys), and
upgrades cue `Type` from a flat default to the real int-mapped label.

Purpose: feed the technics filter (genre ∩ Camelot ∩ BPM), the cue-anchor
mapping in Plan 03 (needs the real cue Type), and the curator/co-host grounding
with the metadata that was free all along. Additive + honest: every new field
coerces to a typed empty on absence (Invariant #3 — missing stays missing).

Output: an enriched `TrackEntry` + a new `TempoNode` dataclass, cue Type
fidelity, a `SCHEMA_VERSION` bump (clean cache invalidation), and extended tests.
This plan runs in PARALLEL with Plan 01 — disjoint file ownership (rekordbox.py
vs the new sources/ + ingest.py).
</objective>

<objective>
Extend the existing `learn-progress.json` persistence layer to carry a forward-compatible
`skills` live-portion block, bumping `SCHEMA_VERSION` 1→2 with an explicit `_migrate_v1_to_v2`
upgrader, preserving corrupt-recovery + reset, and reusing the shipped atomic-write idiom verbatim.

Purpose: This is the data-model floor the Wave-2 `skill_tree.py` engine reads. The learn-portion
(fill + competent bool) is DERIVED by the engine on every load; only the live-portion
(`live_proof_count`/`mastered`/`first_mastered_at`) is STORED here, with safe defaults Phase 103
will fill. Getting the migration right (route v1 through the upgrader, NOT the wipe seam) is the
single highest-risk edit in the phase — RESEARCH finding #1.

Output: A v2 `LearnProgress` schema with a seeded 6-skill `skills` block, a deterministic v1→v2
migration, an idempotent v2 reload, a corrupt-recovery path that seeds an empty v2 block, and a
reset path that clears the live-portion. Implements DATA-01, DATA-02, DATA-03.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| disk → process | `learn-progress.json` is read at load; attacker-modified / truncated / schema-drifted bytes cross here |
| skill-state → profile.json | skill data must NEVER reach the `additionalProperties:false` privacy contract |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-102-01 | Tampering | `save_progress` half-truncated write | mitigate | Reuse the shipped atomic `tmp.write_text`→`os.replace` idiom verbatim (POSIX rename / Windows ReplaceFileW are atomic); do NOT hand-roll a new write path |
| T-102-02 | Denial of Service | corrupt `learn-progress.json` wedges load | mitigate | `load_progress` catches `OSError|JSONDecodeError` → unlink → fresh-empty `LearnProgress()` whose `skills` default_factory seeds an empty v2 block; `was_corrupt=True` returned (existing path extended) |
| T-102-03 | Tampering | schema_version drift (v1 file post-bump) | mitigate | Explicit `_migrate_v1_to_v2` upgrader routed inside `from_dict` on `schema_version == 1`; v3+/garbage still hits the fresh-empty wipe seam (DATA-02) |
| T-102-04 | Information Disclosure | skill data leaking into `profile.json` | mitigate | `progress.py`/`ipc_handlers.py` never import/write `profile.schema`; skills live only in `learn-progress.json`. Pinned by `test_skills_never_in_profile_json` (Plan 02) |
| T-102-05 | Tampering | non-idempotent migration clobbers P103 live data | mitigate | Migration gated strictly on `schema_version == 1`; a v2 file with non-zero `live_proof_count` loads untouched (pinned by `test_migration_idempotent_preserves_live_portion`) |
</threat_model>

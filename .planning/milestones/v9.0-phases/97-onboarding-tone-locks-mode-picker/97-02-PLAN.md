<why>The 300 hints (`["DJControl Inpulse 300"]`) are a substring of the MK2 hints (`["DJControl Inpulse 300 MK2"]`). `find_mapping` sorts profiles alphabetically — `hercules_inpulse_300` would match BEFORE `hercules_inpulse_300_mk2`. Pin the disambiguation by adding `"MK2"` as the first hint in the MK2 profile so a port name containing "MK2" matches the MK2 profile first.</why>
<how>
1. Write a new test `tests/midi/test_hercules_300_mk2_disambiguation.py`:
   - Asserts `find_mapping("DJControl Inpulse 300 MIDI 1")` returns the 300 profile.
   - Asserts `find_mapping("DJControl Inpulse 300 MK2 MIDI 1")` returns the MK2 profile.
   - Negative-control: empty string returns None.
2. If the test fails in the MK2-port direction (the current substring-and-alphabetic-tiebreak logic in `registry.py::find_mapping` lines 33-41 means `inpulse 300` matches both AND alphabetic tiebreak picks `hercules_inpulse_300` first), add a deterministic disambiguation:
   - Sort profiles by `id` but with a LONGER-HINT tiebreak — the profile with the longest matching hint wins. OR: add an MK2-first `"MK2"` standalone hint to the MK2 profile (simpler — keeps the registry pure-substring).
   - Recommended fix: add hint `"MK2"` to the MK2 profile and have `find_mapping` prefer the LONGEST matching hint length across all profiles, breaking ties alphabetically. This is a small surgical change in `src/vibemix/midi/registry.py::find_mapping`.
3. Re-run the test until both directions pass.
</how>

`ControllerState.deck_snapshot()` (existing, `src/vibemix/midi/state.py:144`):
- Returns a lock-guarded dict shaped `{"A": {field: int, ...}, "B": {field: int, ...}, "xfader": int, "connected": bool}`.

`port_watcher_task` (existing, `src/vibemix/midi/watcher.py:41`):

- On change, fires an `on_change` callback with `("connected", port_name, profile)` or `("disconnected", port_name)`.
- The callback may be sync (returning None) or async (returning a coroutine the watcher awaits transparently) — see `_safe_invoke` at `watcher.py:110`.
- The `handle_port_change_single_state` adapter in `platform/_midi_common.py` is where the callback currently lands; we LAYER ON TOP (do NOT replace).

`ws_broadcast` (existing, `src/vibemix/runtime/ws_bus.py:276+`):
- Async loop ticking at 30 Hz on the asyncio main loop; the mascot frame and snapshot frame are emitted inside this loop.
- The `_send_all(envelope_dict)` helper is a CLOSURE inside `ws_broadcast` — it is NOT callable from the port_watcher callback path. Cross-thread / cross-coroutine callers must enqueue work that the tick drains instead of calling `_send_all` directly.
- Already accepts kwargs (`levels`, `state`, `transcript_buf`, `controller_state`, `suggestion_holder`, `tracer`, `ipc_router`, `screen_available`); we add ONE new kwarg `midi_mirror=None`.
- The 30 Hz tick is `await asyncio.sleep(1.0 / 30)`; mascot/snapshot emit happens before the sleep; we add a drain-then-snapshot block immediately after the mascot emit, before the sleep.

`__main__.main()` (existing, `src/vibemix/__main__.py:843+`):
- Instantiates `midi_macos = MidiMacOS()` (or Windows equivalent on Windows) at ~line 844.
- Calls `asyncio.create_task(ws_broadcast(...))` later; we insert `midi_mirror = MidiMirror(controller_state=midi_macos.controller_state)` between these two events and thread it into the `ws_broadcast(...)` kwarg list.

### The cross-boundary contract (the bit the plan-checker flagged)

The `port_watcher_task` callback runs on the asyncio main loop (NOT a worker thread), so technically a callback could `await` on an asyncio queue. BUT the live co-host path expects the `_send_all` consumer to run inside `ws_broadcast` — it's a closure over the connected-clients set with no external handle. Layering an alternate emit path from the port_watcher callback would either:
  (a) require lifting `_send_all` out of the closure (a bigger refactor than P91 wants), or
  (b) require a second `websockets.serve` (forbidden by Invariant #4).

So the contract for P91 is: ALL `ipc.learn.*` emits leave through the SAME `ws_broadcast` 30 Hz tick. The port_watcher callback ENQUEUES a `controller_detected` envelope into a `MidiMirror`-owned thread-safe `list[dict]` (guarded by `threading.Lock` — the protocol is identical to how `ControllerState` guards its dict, which keeps the threading discipline uniform and means a future Rust-direct midir path or worker-thread caller works without rework). The 30 Hz tick drains that queue once per iteration BEFORE pushing the position frame.

This is the pattern the existing snapshot-broadcast path uses (sidecar produces; tick emits) — we are NOT introducing a new mechanism, we are following the established convention.

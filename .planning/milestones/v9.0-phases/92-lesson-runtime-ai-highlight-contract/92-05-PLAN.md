    **Step 2 — Add `applyHighlight` export** to `controller-stage.ts`. Per 92-RESEARCH.md §Pattern 5 lines 700-755 (copy verbatim with minor type tightening):

    ```typescript
    /**
     * Phase 92 (RENDER-04) — paints a highlight on the target <g data-control-id>
     * group by swapping `data-cue-color` + `data-cue-shape` attributes.
     *
     * The CSS-variable cascade (learn.css line 142-143 — P91 scaffolded) does the
     * actual paint via currentColor → var(--learn-highlight) for color and via
     * the .cue-shape::before pseudo-element for the pulse-ring animation.
     *
     * ≤16 ms P95 paint budget pinned by tauri/ui/tests/learn/highlight-paint.test.ts.
     * Single-active invariant: only ONE control is lit at a time. The function
     * clears any prior [data-cue-color] before setting the new one.
     */
    export function applyHighlight(
      stage: HTMLElement,
      payload: {
        control_id: string;
        deck: string;
        cue_color: "amber" | "warning";
        cue_shape: "pulse-ring" | "static-glow";
        annotation?: string;
        expected_action?: object;
      }
    ): void {
      // Clear any prior highlight (single-active invariant).
      stage.querySelectorAll<SVGGElement>("[data-cue-color]").forEach((g) => {
        g.removeAttribute("data-cue-color");
        g.removeAttribute("data-cue-shape");
      });
      // Resolve target ID — bare control_id for master section, "<field>:<deck>" otherwise.
      const targetId = payload.deck
        ? `${payload.control_id}:${payload.deck}`
        : payload.control_id;
      const target = stage.querySelector<SVGGElement>(
        `[data-control-id="${targetId}"]`,
      );
      if (!target) {
        console.warn(`[learn] highlight: control_id "${targetId}" not found`);
        return;
      }
      target.setAttribute("data-cue-color", payload.cue_color);
      target.setAttribute("data-cue-shape", payload.cue_shape);
    }

    /** Clear the active highlight (used on `ipc.learn.advance`). */
    export function clearHighlight(stage: HTMLElement): void {
      stage.querySelectorAll<SVGGElement>("[data-cue-color]").forEach((g) => {
        g.removeAttribute("data-cue-color");
        g.removeAttribute("data-cue-shape");
      });
    }
    ```

        hintLines.innerHTML = "";

    **Step 4 — Add MIDI-ack emit on physical control press** (bridges the existing P91 midi_position stream into `ipc.learn.ack` for the LessonRuntime to evaluate). When a `midi_position` envelope arrives + the value changed AND a lesson is active AND the changed control matches the expected_action's control_id, emit `ipc.learn.ack` so the LessonRuntime can call `action_matches` and advance. Implementation tip: track the last-known position per control_id; on change, emit ack. Or — simpler — emit ack on EVERY position change while a lesson is active; the LessonRuntime's `action_matches` filter does the work.

    Simpler implementation:

    ```typescript
    let lastPositions: Record<string, number> = {};
    window.addEventListener("ipc.learn.midi_position", (ev: Event) => {
      const payload = (ev as CustomEvent).detail.payload;
      // Existing P91 handler updates the stage; preserve that behavior
      // ADDITION: emit ack for any changed control while a lesson is active
      if (!currentLessonId) return;
      for (const [controlId, value] of Object.entries(payload.positions ?? {})) {
        const prev = lastPositions[controlId];
        if (prev === undefined) {
          lastPositions[controlId] = value as number;
          continue;
        }
        const delta = Math.abs((value as number) - prev);
        if (delta > 0) {
          // Detect direction for button-like controls (value 0 → >0 = "down")
          const direction = (value as number) > prev ? "down" : "up";
          void emitIpc("ipc.learn.ack", {
            control_id: controlId,
            source: "midi",
            value: value as number,
            direction,
          });
          lastPositions[controlId] = value as number;
        }
      }
    });
    ```

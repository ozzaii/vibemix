        "search_vibe": self.search_vibe,
        # ... existing handler map

    handler = handlers.get(name)
    if handler is None:
        return {"error": f"unknown tool {name!r}"}
    with concurrent.futures.ThreadPoolExecutor(max_workers=1) as ex:
        fut = ex.submit(handler, args)
        try:
            result = fut.result(timeout=TOOL_CALL_TIMEOUT_S)

- Writing counter updates INSIDE handler bodies (e.g. inside `search_vibe`) — that runs on the `ThreadPoolExecutor` worker thread (Pitfall 1). Counter writes MUST happen in `dispatch()` AFTER `fut.result()` returns.

- Inlining `3` in any comparison — always reference `tool_mod.TOOL_STARVATION_THRESHOLD` (Pitfall 7).

- Treating empty `discover_pool` / `get_track_features` results as empty-triggers — only `search_vibe` empty counts. Other handlers count only when they return `{"error": ...}` (D-02 locked; see RESEARCH.md Open Question 3).

Bounded indirectly: once Plan 99-03 lands, the threshold trip writes `stop_reason` and Plan 99-03's short-circuit prevents further increment past threshold.

## Summary of corrections / flags

- **Claim 1b (250k MAU):** factually CONFIRMED but **mis-dated in the research**. The research attributes the 250k-MAU gate loosely; it actually lands in Spotify's **2025-04-15** "Updating the Criteria for Web API Extended Access" post (effective 2025-05-15), separate from the **2024-11-27** endpoint deprecation. Recommend the research note both dates distinctly.
- **NEW (claim 1c):** Spotify tightened *again* on **2026-02-06** (Premium-required dev mode, test users 25→5, more endpoints cut). This post-dates the research and only strengthens its "skip Spotify" verdict — worth adding so the doc doesn't read as stale.
- Everything else (Beatport non-commercial/domain-lock/link-back, MB 1 rps + UA, AcoustID 3 rps + key + no BPM/key, Discogs 60/25 rpm + no BPM/key, SoundCloud closed, 1001TL scrape-only) is **CONFIRMED against current official sources** with no drift.

## Caveats

- Beatport T&C and Discogs accessing.html return **HTTP 403** to direct programmatic fetch (anti-bot); their text was verified via search-engine index of the same official URLs, not a live page render. Verdicts hold but were not byte-confirmed from a live fetch.
- context7 MCP unavailable this session, so no SDK-doc cross-check (spotipy/musicbrainzngs/pyacoustid/discogs_client). Not load-bearing — the claims are about API *policy/limits*, which the official sources cover directly.

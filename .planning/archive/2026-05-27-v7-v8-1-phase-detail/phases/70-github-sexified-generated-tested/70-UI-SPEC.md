Out of scope for this spec: the asset-pipeline infra (`regenerate_assets.sh`, `MANIFEST.yaml`, `asset-bitrot.yml` — Wave 0), the demo.mp4 capture (KAAN-ACTION §ASSETS-DEMO-CUT), and the `test_github_presence.py` suite (Wave 4). ## Design System

| Property | Value |
|----------|-------|
| Tool | none (plain static HTML/CSS/JS — no framework, no bundler, no build step; HARD constraint per GitHub-Pages-native + the single-file `mocks/*.html` precedent) |
| Preset | not applicable |
| Component library | none — hand-authored CDJ-Whisper CSS, self-contained `<style>` + a Google Fonts `<link>` (mirrors `mocks/vibemix-direction-final.html`) |
| Icon library | none — inline SVG only (matches mock; the tray/mascot/LED affordances are inline `<svg>` or CSS shapes). No icon-font, no external icon dep. |
| Font | **Saira** (display + body) + **JetBrains Mono** (numerals/code/labels) via Google Fonts. Variable Saira axes used (`wdth` 75..125, `wght` 300..800). |

**Self-containment contract (no-build):**
- All CSS lives in an inline `<style>` block (or a single co-located `docs/landing/style.css` linked relatively — executor's call, no bundler either way).
- Google Fonts loaded via `<link rel="preconnect">` + `<link href="…Saira…JetBrains+Mono…">` exactly as the mock does. No npm font package, no self-hosted woff build step.
- All JS is vanilla, inline or a single co-located `docs/landing/app.js`. No module bundler, no transpile.
- **Anti-backsliding gate (HARD):** `grep -ri 'geist\|fraunces' docs/landing/` MUST return zero. Also forbidden: Inter, Roboto, Arial, system-ui *as a primary face* (system-ui may only appear inside the font-family fallback chain after Saira, exactly as the mock writes `'Saira', system-ui, sans-serif`).

## Layout Contract

Single-page, mobile-first, top-to-bottom scroll. Semantic landmarks are mandatory (a11y ≥95).

**Document structure (semantic order):**
```
<header>   — sticky meta-bar: vibemix wordmark + amber brand LED + version/tag mono text
<main>
  §1 Hero            — "what is this in 30 seconds" (above the fold on desktop)
  §2 Demo embed      — the README <video> poster pattern (poster → demo.mp4 when it lands)
  §3 Install CTA      — the primary conversion block
  §4 Waitlist opt-in — opt-in Bravoh-waitlist hook (default-OFF, no tracking on view)
<footer>   — OSS links: GitHub repo · CONTRIBUTING · LICENSE · SECURITY
```

### §1 Hero (above fold)
- Two-zone layout echoing the mock's `.brief`: headline column + lede column. On desktop a `grid-template-columns: 1.1fr 1fr` (mock value); collapses to a single stacked column ≤ 900px.
- Headline = the 30-second pitch (1 line + 1 amber accent line, see Copywriting). Saira display, condensed-heavy.
- A single amber brand LED (the `.meta-bar .brand::before` 5px pulsing dot, `brandPulse 5s`) lives in the header, not sprinkled into the hero body — that's the only LED above the demo.
- Hero sits over the mock's cinematic center-vignette background (`radial-gradient` ellipse + `linear-gradient(180deg, #02030a 0%, #000 55%, #030208 100%)`) + the two-layer SVG film-grain `body::before`. Lift verbatim.

### §2 Demo embed
- Reuse the README hero pattern: `<video controls muted playsinline poster="../assets/demo-poster.png">` with the `<img>` poster fallback inside. Until `demo.mp4` lands (KAAN-ACTION §ASSETS-DEMO-CUT), the poster carries the visual; the `<video>` `src` may point at the not-yet-present `docs/assets/demo.mp4` (the poster + fallback `<img>` keep it non-broken — same contract as the README).
- The video sits in a recessed glass display window — reuse the mock's `.display-window` treatment (near-solid `--glass-3`, deep inset shadow, the top-edge specular `::after` gradient). This is the landing's "screen", echoing the app UI's time-hero LCD.
- Poster `<img>` MUST have descriptive `alt` (see Accessibility).
- Aspect ratio reserved with `aspect-ratio: 16/9` (or the poster's intrinsic ratio) to avoid CLS — protects the Lighthouse perf ≥90 score.

### §3 Install CTA block
- The primary conversion surface. One **amber-filled** primary button (`.btn.on` treatment from the mock — internal amber backlight + 1px amber edge) labelled per Copywriting.
- Directly beneath: a JetBrains-Mono code one-liner block showing the install command(s) from Phase 69's packaging scaffolds — `brew install …` (mac) and `scoop install …` (win). Render in a recessed glass tile (`--glass-3` inset) with `--type-mono`, `--silk` ink, `font-variant-numeric: tabular-nums`. A small copy-to-clipboard affordance is allowed (vanilla JS, `navigator.clipboard.writeText`) — degrade gracefully (still selectable text) if clipboard API is absent.
- Platform split (mac / win) shown as two `.mood-block`-style segmented tiles OR two stacked mono lines — executor's call; keep amber only on the active/primary, not both.

### §4 Waitlist opt-in block
- The Bravoh-waitlist hook. **Default-OFF**: NO analytics/tracking script auto-loads on page view (privacy + anti-slop — locked v3.0 funnel rule). The UTM-tracked link only fires on click-through.
- Visual: a secondary (NOT amber-filled) `.btn` idle-state tile by default. The amber treatment + the UTM-tracked outbound `<a>` is revealed/activated only on user interaction (a click reveals the link, or the button IS the link with no pre-load tracking — implementation detail; the contract is "zero network/tracking on page view").
- Microcopy frames it as a Bravoh sibling, not a hard sell (see Copywriting).
- Waitlist destination URL: **placeholder** `https://altidus.world/waitlist?utm_source=vibemix&utm_medium=landing&utm_campaign=oss` — the real canonical URL is unknown at execution → routed to `KAAN-ACTION-LEGAL.md §V7-LANDING`. The UTM params above are the locked shape.

### Footer
- OSS links row, JetBrains-Mono small text (mock `footer` treatment: 10px mono, `--silk-40`, amber links). Links: GitHub repo · CONTRIBUTING.md · LICENSE (Apache-2.0) · SECURITY.md · CODE_OF_CONDUCT.md. License/version line on the right.

### Responsive breakpoints (mobile-first)
| Breakpoint | Behavior |
|------------|----------|
| Base (≤ 600px, phone) | Single column. Hero headline scales down (see Typography responsive clamps). Demo full-width. CTA + waitlist stack. Touch targets ≥ 44px. |
| 601–900px (tablet) | Single column, larger hero. Demo capped at readable width. |
| ≥ 901px (desktop) | Hero two-column grid (`1.1fr 1fr`). Max content width ~1100px, centered. |

Mobile-first is a HARD requirement — the landing must be fully readable + the CTA tappable on a phone (most IG-ad click-throughs are mobile).

## Typography

Source: `mocks/vibemix-direction-final.html` type stack (§03). Saira is variable — width + weight axes via `font-variation-settings`. Exactly two families, deliberate weight set. Headings condensed-heavy uppercase; body normal-width; numerals/labels/code mono.

| Role | Family | Size | Weight (var settings) | Line Height | Notes |
|------|--------|------|----------------------|-------------|-------|
| Hero display | Saira | `clamp(40px, 9vw, 88px)` | `wdth 82, wght 700` | 0.90 | UPPERCASE, `letter-spacing: -0.02em`. The 30-sec pitch headline. Amber accent line uses `wght 800`. |
| Section heading | Saira | 24px | `wdth 85, wght 600` | 1.1 | UPPERCASE. Block titles (Install / Waitlist). |
| Subhead / lede | Saira | `clamp(15px, 2.2vw, 18px)` | `wdth 100, wght 400` | 1.6 | The 1-sentence subhead under the hero. `--silk-65`. Max-width ~50ch. |
| Body | Saira | 15px | `wdth 100, wght 400` | 1.6 | Supporting prose. `--silk-65`. |
| Silkscreen label | Saira | 10px | `wdth 85–90, wght 500` | 1.2 | UPPERCASE, `letter-spacing: 0.18em`, `--silk-65`. Eyebrow labels, status tags. |
| CTA label | Saira | 10–12px | `wdth 85, wght 600` | 1 | UPPERCASE, `letter-spacing: 0.18em`. The install button + waitlist button. |
| Code / numerals | JetBrains Mono | 11–14px | 400–500 | 1.4 | `font-variant-numeric: tabular-nums`. The `brew install` one-liner, version strings, footer. |

**Declared weight set (deliberate, document the why in CSS comments per frontend-enforcement rule 5):**
- Saira: 400 (body), 500 (labels), 600 (headings/CTA), 700/800 (display) — the variable axis gives the range from a single family; no second sans needed.
- JetBrains Mono: 400, 500 (numerals + code only).

Responsive: hero uses `clamp()` so it never overflows on a 360px phone while staying impactful on desktop. Body/lede also `clamp()` to stay readable on mobile.

## Color

20/80 rule (frontend-enforcement HARD rule 2): ~80% warm-black/silk surface, ~20% amber accent — amber appears ONLY on the listed elements, never spread across the surface. Lift every value verbatim from the mock `:root`.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (≈80%) | Void stack: `--void #000000` · `--void-1 #020205` · `--void-2 #05070b` · `--void-3 #0a0c12` · `--void-4 #11141c` | Page bg (`#000` base + cinematic vignette + `linear-gradient(180deg,#02030a,#000,#030208)`), panel layering. |
| Surface / panels | Glass: `--glass-1 rgba(8,10,16,0.78)` (primary panel) · `--glass-2 rgba(12,14,22,0.62)` (secondary) · `--glass-3 rgba(2,3,6,0.88)` (recessed: demo window, code tile, waitlist idle) | Cards, demo window, install tile. Backdrop-blur per `--blur-glass*`. |
| Ink | Silk: `--silk #d6cfc7` (headlines, primary text) · `--silk-65` (lede/body) · `--silk-40` (muted labels, footer) · `--silk-22 / --silk-12` (dividers, hairlines) | Headline = full silk; body = silk-65; muted/footer = silk-40. |
| Accent (≈20%) | `--amber #ff8a3d` (primary) · `--amber-deep #ff5a1a` · `--amber-pale #ffb88a` · `--amber-22/40/65` (glow alphas) | See reserved-for list below. |
| Status LEDs (semantic, used sparingly) | `--led-ok #6dd44a` · `--led-warn #f4c542` · `--led-fault #d4413a` | Optional: a single "open source · live" ok-LED in the footer/header. Not required; if present, hardware-dome treatment from the mock. NOT a destructive-action surface (the landing has no destructive actions). |

**Accent reserved for (explicit — never "all interactive elements"):**
1. The header brand LED (5px pulsing amber dot).
2. The install CTA primary button (`.btn.on` internal amber backlight + 1px amber edge + amber label).
3. The hero headline accent line (one line of the 2-line headline, amber with soft glow — the `.brief .h0 .deck` treatment).
4. Inline `<em>`/keyword emphasis in the lede (the mock's `.lede em { color: var(--amber) }`) — at most one or two words.
5. Footer/inline links (amber, `text-decoration: none` — mock `footer a`).
6. The waitlist button ONLY in its activated/hover state (default idle = secondary silk tile; amber lights on intent).
7. Optional animated amber perimeter sweep on the demo window (`.border-anim`, 22s) — a single "sign of life", reduced-motion-gated (see below).

Everything else is warm-black + silk. If you can't scan the page and instantly see where amber is guiding the eye, the 20/80 rule is broken.

**No flat `#1a1a1a` fills** (frontend-enforcement rule 3): every panel/tile carries material treatment — see Material Treatment below.

**Contrast (WCAG AA — Lighthouse a11y ≥95):**
- `--silk #d6cfc7` on `--void-1 #020205`: contrast ratio ≈ 15.3:1 — passes AA + AAA for all text. ✅
- `--silk-65` (≈ `#8d8884` effective on black) on void: ≈ 7.1:1 — passes AA for normal text. ✅ Use silk-65 for body, NOT for anything below 14px where it could dip; small labels use silk at full or silk-65 only at ≥ 10px uppercase (large-enough tracking keeps legibility).
- `--silk-40` is BELOW AA for body text — restrict to non-essential decorative labels, dividers, and ≥ large mono captions only. NEVER use silk-40 for the CTA label, install command, or any text a user must read to act.
- Amber `#ff8a3d` on `--void`: ≈ 9.8:1 — amber links + amber CTA label on dark pass AA comfortably. ✅
- The amber CTA: when text sits ON an amber fill (if any), it must be `--void` dark text (the mock's `.pal-chip` uses `color:var(--void)` on amber) — verify ≥ 4.5:1. The mock's `.btn.on` keeps the *fill* as a low-alpha amber backlight with amber *text*, which is the safe pattern — prefer that.

| Treatment | Implementation (verbatim from mock) |

NO solid flat fills, NO default Tailwind card-with-rounded-2xl-shadow, NO generic blue/purple gradients. Border radii from mock: `--rad-sm 2px`, `--rad-md 6px`, `--rad-lg 10px` — small, hardware-precise, never `rounded-2xl`.

## Interaction States

All interactive elements need idle / hover / active / focus states. Transitions `180ms ease-out` (mock value).

| Element | Idle | Hover | Active/Pressed | Focus |
|---------|------|-------|----------------|-------|
| Install CTA (primary) | `.btn.on` amber-backlit | amber glow intensifies (`0 0 8px var(--amber-22)` → stronger), slight lift | `inset 0 2px 5px rgba(0,0,0,0.75)` recessed (mock `.btn.pressed`) | **visible amber focus ring** — `outline: 2px solid var(--amber); outline-offset: 2px` (a11y, see below) |
| Waitlist button (secondary) | silk tile, NO amber (default-OFF visual) | silk → full silk + faint amber edge appears | amber lights, outbound UTM link fires | visible focus ring (amber) |
| Copy-command affordance | mono text, copy icon `--silk-40` | icon → `--silk`, faint halo | brief "copied" mono confirmation (vanilla JS) | visible focus ring |
| Footer / inline links | amber, no underline | underline OR brightness lift | — | visible focus ring |
| Demo `<video>` controls | native controls | native | native | native focus (do not suppress) |

**Keyboard focus (a11y ≥95 HARD):** EVERY interactive element (CTA, waitlist, copy button, all links, the video) has a VISIBLE focus indicator. Do NOT `outline: none` without an equivalent amber ring replacement. Focus order follows DOM order (header → hero → demo → install → waitlist → footer) — no positive `tabindex`.

**`prefers-reduced-motion`:** Wrap ALL motion (`brandPulse`, `liveBlink`, `.border-anim` sweep, `mBreathe`, any scroll/hover transforms) in `@media (prefers-reduced-motion: no-preference) { … }` OR add `@media (prefers-reduced-motion: reduce) { *, *::before, *::after { animation: none !important; transition: none !important; } }`. The page must be fully usable + non-distracting with motion off. The amber LED becomes a static dot; the border-sweep stops. (frontend-enforcement rule 6: motion is intentional + atmospheric — and here, dismissible.)

## Accessibility Contract (Lighthouse a11y ≥ 95)

| Dimension | Requirement |
|-----------|-------------|
| Landmarks | Exactly one `<header>`, one `<main>`, one `<footer>`. Sections use `<section>` with an `aria-label` or a heading. |
| Headings | One `<h1>` (the hero pitch). Section titles `<h2>`. No skipped levels. |

| Color contrast | Silk-on-void hits AA+ (verified above). Silk-40 restricted to non-essential text only. Amber CTA + links pass AA. |
| Focus | Visible focus ring on all interactive elements; logical focus order; no positive tabindex; no focus traps. |
| Video | `<video>` has `controls`; poster set; `muted playsinline`; a text description nearby (the hero copy doubles as the description). Captions: the demo has no critical speech for comprehension of the *page*, but if the film carries spoken coach lines, a `<track kind="captions">` is the §ASSETS-DEMO-CUT deliverable — note as KAAN-ACTION, not blocking the engineering close. |

| Meta | `<meta name="viewport" content="width=device-width, initial-scale=1.0">`, descriptive `<title>`, `<meta name="description">`. |
| Touch targets | ≥ 44px on mobile for CTA + waitlist. |
| Reduced motion | Honored (above). |

**Perf ≥ 90 supporting notes (not strictly UI, but the spec enables it):** inline critical CSS (no render-blocking external stylesheet beyond Google Fonts, which uses `&display=swap`); `preconnect` to fonts.gstatic.com; reserve media aspect-ratio to avoid CLS; poster image optimized (the asset pipeline / KAAN poster cut handles size); no heavy JS, no analytics auto-load.

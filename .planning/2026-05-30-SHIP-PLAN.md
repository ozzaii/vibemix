## The 4 blockers (adversarially verified — all confirmed real)

### #1 — End-user key delivery: the downloaded dmg ships a MUTE co-host 👤 kaan/momo
The whole product only speaks if `GEMINI_API_KEY` + `CARTESIA_API_KEY` are present. Keys resolve **only** from a local `.env` (`src/vibemix/__main__.py:210+`, `override=True`); in shipped `direct` mode (`config_store.py:192`) `__main__.py:722-742` hard-exits `[FATAL] … sys.exit(4)` with no key. The bundle ships **no `.env`** (verified), the wizard has **no key-collection step**, and there's **no `/register` proxy path**. So a stranger's download is silent.
**Action:** Kaan/Momo pick one — **(A)** deploy the Bravoh proxy `/api/vibemix/v1/register` (was 404) and point the client at it (the CLAUDE.md-mandated "host the key" path), or **(B)** ship a wizard BYO-key step. The backend/decision is external; **the wizard BYO-key UI + keyring store is claude-now** once (B) is chosen.

### #2 — Stale artifacts: the on-disk dmg/.app are ~2 days behind the engine 🤖 claude-now → FIXING NOW
The existing `vibemix_0.0.1_aarch64.dmg` is May 28; **92 source files are newer**, incl. this session's Cartesia-primary TTS, per-deck zero-config, and 44.1k capture. Demoing the old dmg would show last-week's engine.

### #3 — Adhoc-signed: not distributable (Gatekeeper-rejected on other Macs) 👤 kaan/francesco
`codesign -dv` on the built `.app` = `Signature=adhoc, TeamIdentifier=not set`; `spctl` = `rejected: no usable signature`. But the **`Developer ID Application: Francesco Fasanella (UK7DYFK6F8)` cert IS in the keychain, valid through 2031-03-03**, and `tauri.conf.json5:126-134` already has `hardenedRuntime` + entitlements.
